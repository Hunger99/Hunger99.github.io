On tasks of the trained types, multi-turn agent SFT takes the 4B model from 16.7% to 88.7%, past the official Qwen3.5-4B (57.7%). On long-document QA that the training data does not cover, it stays below the official model.

Abstract

This project post-trains a 4B base model, Qwen3.5-4B-Base, into a tool-using financial agent that looks up market prices, macroeconomic series and company filings, computes over them in a Python sandbox and answers multi-step questions. The official post-trained Qwen3.5-4B already solves 84.7% of our earlier market-retrieval development tasks, so we built a harder offline dataset of 3,148 tasks: 2,850 generated in the style of FinSearchComp over a fixed data snapshot, with answers computed by programs and rechecked by an independent implementation, plus 98 FinSearchComp and 200 DocFinQA test tasks. A Qwen3.8-27B teacher solves the market training tasks of two difficulty tiers in an agent harness; these filtered trajectories, with filtered wealth-management and machine-learning trajectories and 2,000 conversations from the 1:1 mix, train the 4B model with multi-turn agent SFT. On 300 test market-data tasks, on held-out stocks and, for indices, ETFs, FX and FRED series, later periods, the SFT model solves 88.7%, against 57.7% for the official Qwen3.5-4B, 16.7% for the base model and 94.7% for the teacher. Reinforcement learning with GRPO from the SFT model is running now.

This stage turns public financial and general data into training mixes for supervised fine-tuning (SFT). These mixes train the single-turn SFT runs, and the agent SFT model in stage 4 takes 2,000 conversations sampled from the 1:1 mix.

  • Format normalization: Every source is rewritten into one sample format with an id, source, messages and metadata. Later steps can then run the same code on all sources. The rewrite drops samples over 4,096 tokens rather than cutting them, since a cut would keep the reasoning and lose the answer.
  • Synthetic document QA: The model gpt-oss-120b reads a finance passage of 1,000 to 2,000 characters and writes a calculation question with its worked answer. This extends the read-and-compute task type beyond annual reports. A sample stays only if its numbers appear in the passage and a second answer from the same passage agrees within 1%.
  • Decontamination: This step deletes training samples that repeat or closely copy an evaluation task. Otherwise a score could come from a task the model has already seen. A sample is flagged when shared runs of 8 tokens cover at least half of an evaluation task, when the same check passes after table and JSON formatting is stripped, when either of two embedding models finds it too similar, or when it shares enough numbers with an annual-report excerpt.
  • Grounding filter: This filter deletes samples of the financial instruction dataset IndustryInstruction whose answer uses material the prompt does not include. Such samples teach the model to write numbers that are not in its material. A sample goes when a short prompt cites an article or data it leaves out, or when the answer has two or more specific numbers missing from the prompt.
  • Deduplication: This step keeps one sample per question. The same FinQA task also appears in the DianJin and BizBench datasets, and the FinQA version ranks first because a standard program produced its solution. Samples built on a document excerpt match when the normalized question is the same and the excerpts' number sets have a Jaccard similarity of at least 0.5; the others match exactly or by MinHash at 0.9.
  • Mixing: Each SFT run draws 100,000 samples from a finance pool of 143,442 and a general pool of 829,947 at a set ratio. Finance-only SFT can erase the base model's general skills, so the ratio sets how much general data protects them. Finance sources are sampled by size with a 40% cap per source, and a smaller draw nests inside a larger one.

The harness wraps the model for multi-step tasks: it supplies the system prompt and tools, runs the tool calls, checks the answer and grades it. The model ends a task by calling the finish tool with its answer. These bullets describe the full configuration of version 3, which the teacher used on the market tasks.

  • Append-only context: No message changes after it is sent, so each model call's messages are a prefix of the next call's and of the stored trajectory. Market SFT data and GRPO then use the message sequence the model saw. Older results are never summarized; each tool result is cut at 8,000 characters when it is produced, with a note on how to ask for less.
  • Checklist tool: set_checklist lets the model write the steps a request needs and mark them done. It keeps sub-goals in view during a long task. The harness restates the checklist after every tool result, and the model may call the tool at most 20 times in a task.
  • Separate step budgets: The limit of 100 steps counts only task turns, the turns that do the task's work. Checklist upkeep and redoing a rejected answer should not use up the steps a long task needs. A checklist-only turn, a turn with a rejected finish and the 10 turns after it do not count, under a hard cap of 142 turns.
  • Constraints: Code checks every write action against the tool schema and the checkable business rules before running it. A trade that breaks a rule should never reach the account. A breaking write is rejected unexecuted and the model gets the reason. Market tools only read data, so this part acts in the wealth-management environment.
  • Answer verification: When the model calls finish, the answer's numbers, apart from exceptions such as dates, must have support in the tool results or the request, every checklist item must be done, and the environment's own checks must pass, such as each trade meeting the rules on the final state. This targets numbers no tool produced and answers given before the work is done. On market tasks a number counts as supported when a tool-result number matches it after scaling by thousands, millions, billions or percent and rounding to the answer's decimals. A failed check rejects the finish at most twice; the next finish is accepted unchecked, and the SFT filters drop such trajectories.
  • Correction messages: These messages tell the model what went wrong. They aim to stop loops and wasted steps. A rejected finish returns the failing checks, a tool error on a known tool returns an example of a valid call, the third identical call gets a hint to change approach, and a reply with no tool call gets a reminder.
  • Thinking-preserving chat template: This changed Qwen3.5 template, used to serve the 4B models in harness version 3 and to render market SFT data, keeps the thinking of every assistant turn after the first user message. The original template dropped earlier thinking after a reminder, so the next prompt no longer extended the last one. Each turn records its sampled tokens and whether its prompt begins with the previous prompt and completion, so any break shows up.

Market trajectories from the Qwen3.8-27B teacher pass up to 11 filters, such as a correct answer, no repeated calls, a teacher check of the method, and a limit on tasks the base model already solves. Wealth-management and machine-learning trajectories pass the 7 that apply to them. With 2,000 conversations from the 1:1 mix they make 12,475 samples. Several samples share one training sequence of up to 32,768 tokens, which gives 2,439 sequences. Training fine-tunes all of Qwen3.5-4B-Base for 2 epochs at a learning rate of 1e-5 on 6 GPUs.

  • Loss: Training minimizes the cross-entropy between the model's next-token prediction and the label, the standard causal-LM loss \(\mathcal{L} = -\frac{1}{N}\sum_{t:\, y_t \neq -100} \log p_\theta(y_t \mid x_{<t})\), where \(x_{<t}\) is the sequence before position \(t\), \(\theta\) the model weights and \(N\) the number of labeled tokens. This makes the model reproduce the labeled turns token by token. The loss is computed only at labeled positions, in chunks recomputed during the backward pass, which leaves its value and gradients unchanged and saves the memory of full-vocabulary logits at every position.
  • Labels: A label is the token itself where the model should learn and −100, which the loss ignores, everywhere else. Tool outputs come from the tools, so they are not imitated. The labels cover a trajectory's assistant turns: thinking, text and tool calls through the end token. System, user and tool turns are masked. Market trajectories also leave out a reply that drew a reminder and a turn with a rejected call, which stay in the context. Wealth-management and machine-learning trajectories keep the loss on rejected turns, and any with a reminder are dropped. The current data builder also masks turns with malformed calls, such as unknown tool names; the SFT model's data predates this rule, and those turns are 0.25% of its labeled tokens.
  • Sample boundaries: Each batch tells the model where every sample in a shared sequence begins and ends. Without this, Qwen3.5's linear-attention layers would carry state from one sample into the next. With it, the largest per-token loss difference from this leak fell from 6.3 nats to 0.13 nats, which is numerical noise.

Programs score every SFT model on the sets below. Two models are compared task by task: \(\Delta = \frac{1}{n}\sum_{i=1}^{n}(b_i - a_i)\), where \(a_i\) and \(b_i\) are 100 for a correct task and 0 otherwise, and the 95% interval comes from 10,000 paired bootstrap resamples of the \(n\) tasks.

Single-turn SFT runs

  • Finance score (1,886 FinQA and TAT-QA test questions): A question is correct when the first number after the last "Answer:" is within 1% of the reference, in either percent or decimal form. Here \(D\) is the question set, \(y_i\) the reference, \(\hat{y}_i\) the answer and \(\tau_i = 0.01|y_i|\), or 0.005 when \(y_i = 0\). \[A_{\text{fin}} = \frac{100}{|D|}\sum_{i \in D}\mathbf{1}\Big[\min_{k \in \{1,\,100,\,0.01\}}|k\hat{y}_i - y_i| \le \tau_i\Big]\]
  • MMLU (13,018 questions): A question from the knowledge benchmark, without its four economics and accounting subjects, is correct when the most likely option \(o\) for prompt \(x_q\) is the right option \(o^{*}_q\); \(Q\) is the question set. \[A_{\text{MMLU}} = \frac{100}{|Q|}\sum_{q \in Q}\mathbf{1}\Big[\arg\max_{o}\log p(o \mid x_q) = o^{*}_q\Big]\]
  • GSM8K (1,319 questions): A math word problem is correct when \(\hat{a}_q\), the last number in the reply, equals the reference \(a_q\); \(Q\) is the question set. \[A_{\text{GSM}} = \frac{100}{|Q|}\sum_{q \in Q}\mathbf{1}[\hat{a}_q = a_q]\]
  • IFEval (541 prompts): A prompt counts only when the reply meets all its program-checkable instructions \(I_p\), such as a word limit or JSON output; \(P\) is the prompt set and \(f_{p,j}=1\) when instruction \(j\) holds. \[A_{\text{IF}} = \frac{100}{|P|}\sum_{p \in P}\prod_{j \in I_p} f_{p,j}\]
  • General score: The mean of the three general benchmarks. \[A_{\text{gen}} = \tfrac{1}{3}(A_{\text{MMLU}} + A_{\text{GSM}} + A_{\text{IF}})\]

Agent SFT model

  • Market-data test (300 tasks): A task in the set \(T\) passes (\(s_t = 1\)) when every key of its reference, a number within tolerance, a date, a text or a set, appears correctly in the final answer. \[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • FinSearchComp, offline (98 tasks): A task passes under the same key rule, using the tolerance each task states. \[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • DocFinQA (200 tasks): A question over a full SEC 10-K passes when the agent’s number is within 1% of the reference, by the finance-score rule. \[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • Wealth management + ML (550 tasks): One of the 500 wealth-management tasks passes when the final holdings, cash and trade records match the reference and the key numbers in the answer are within tolerance; on a task the rules forbid, the banned trade must not run and the answer must name the rule. One of the 50 machine-learning tasks passes when a model is submitted and scores at most 0.015 AUC or 0.03 \(R^2\) below the model that generated the data. \[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • Development set (200 tasks, 4 attempts each): pass@1 is the average pass rate of one attempt, and pass@4 is the share of tasks solved at least once; \(T\) is the tasks with 4 valid attempts, and \(c_t\) of the \(n_t\) valid attempts at task \(t\) pass. \[P_1 = \frac{100}{|T|}\sum_{t \in T}\frac{c_t}{n_t}, \qquad P_4 = \frac{100}{|T|}\sum_{t \in T}\mathbf{1}[c_t \ge 1]\]

GRPO in verl continues from the SFT model, with ablations on training tasks screened by the SFT model's pass rate, the number of updates per step, and DAPO-style dynamic sampling. GRPO 1 has finished and GRPO 2 is training.

  • GRPO: This reinforcement learning method samples a group of attempts at each task and scores each attempt against its group. The group mean serves as the baseline, so no value network is needed. Each step, run in the RL framework verl, takes 96 tasks with 8 attempts each, and an attempt earns reward 1 when the grader passes it and 0 otherwise.
  • Ablation: Each setting changes one factor of the setting before it. A score difference between neighbouring settings can then be traced to that factor, except that GRPO 1 and 2 also differ in the first 4 steps of GRPO 1. The table below lists the four settings.
  • Pass-rate screening: The SFT model tries each candidate training task 8 times, and its pass rate decides whether the task stays. A group of attempts with equal rewards gives GRPO nothing to compare. Of 2,000 newly generated tasks that repeat no SFT task and no generated development or test task, those never solved went, those sometimes solved stayed and 10% of those always solved stayed; a per-template cut then took the 1,123 kept to 939, the size of GRPO 1's set.
  • Updates per step: This is how many times the weights change on one batch of attempts. It sets how far the model moves on each costly batch. A mini-batch of 24 tasks instead of 96 gives 4 updates a step and 112 in all.
  • DAPO-style dynamic sampling: A group whose 8 rewards are all equal is dropped and replaced during the step. Such a group has zero advantage, so it costs generation time and gives no signal. Each dropped group earns 2 refill tasks, and once a step has dispatched 288 tasks, three times the batch, filtering stops for that step.
  • Attempt limits: An attempt stops at 30 task turns or at a budget of 28,672 tokens after the prompt, tool results included. With the 4,096-token prompt, this matches the 32,768-token SFT sequences. An attempt cut by the budget keeps reward 0 in its group but carries no loss, since the cut is not the model's choice.

The SFT model and the last checkpoint of each GRPO setting run the sets below, so their results pair task by task.

  • Market-data test (300 tasks): A task in the set \(T\) passes (\(s_t = 1\)) by the same key rule as in the SFT evaluation. \[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • Strict market-data grading (same 300 tasks; also run on FinSearchComp and the development set): An answer must also pass four rules (\(r_t = 1\)): at most 50 numbers outside dates, at most 40 distinct dates, each number key found outside any date, and, on tasks with candidates, a correct company named first and each later company key followed by its value. \[S_{\text{strict}} = \frac{100}{|T|}\sum_{t \in T} s_t\, r_t\]
  • FinSearchComp, offline (98 tasks): A task passes by the same key rule as in the SFT evaluation. \[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • DocFinQA (200 tasks): A question passes within 1% of the reference, as in the SFT evaluation. \[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • Wealth management + ML (550 tasks): A task passes by the same state and metric rules as in the SFT evaluation. \[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • Development set (200 tasks, 4 attempts each): pass@1 and pass@4 are defined as in the SFT evaluation, over the tasks \(T\) with 4 valid attempts, and validation during training runs on these tasks every 4 steps. \[P_1 = \frac{100}{|T|}\sum_{t \in T}\frac{c_t}{n_t}, \qquad P_4 = \frac{100}{|T|}\sum_{t \in T}\mathbf{1}[c_t \ge 1]\]
  • Reworded market-data test (300 tasks): The same tasks are rewritten in new wording with the same parameters and answers, and a change shows how much a score depends on the wording. \[\Delta_{\text{reword}} = S_{\text{reworded}} - S_{\text{original}}\]
  • General ability (MMLU, GSM8K, IFEval): The three benchmarks are scored as in the SFT evaluation, except that IFEval uses the model’s own chat template instead of the single-turn runs’ training template, and scores only the text after its thinking. \[A_{\text{gen}} = \tfrac{1}{3}(A_{\text{MMLU}} + A_{\text{GSM}} + A_{\text{IF}})\]
  • Gain over the SFT model: On each task-based set above, \(a_i\) is the SFT model and \(b_i\) the checkpoint on task \(i\), with the same paired bootstrap as in the SFT evaluation. \[\Delta = \frac{1}{n}\sum_{i=1}^{n}(b_i - a_i)\]

Half general data keeps math ability during financial SFT

On Qwen3-4B-Base with 100,000 SFT samples per run, finance-only SFT lowers GSM8K by 30.4 points below the base model, while a 1:1 mix of financial and general data stays within 1.1 points of it and loses 1.5 points of financial score against finance-only SFT. The general data includes GSM8K-style training tasks, so part of this gap comes from practice on similar tasks.
