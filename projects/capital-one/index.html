Abstract

This project compares nine post-training settings for Qwen3.5-4B-Base using DocFinQA, IFEval, FinDeepResearch and one combined 561-question DS-1000 Python analysis subset. Supervised fine-tuning (SFT) learns from verified demonstrations; DAPO learns from tool-assisted attempts and task-specific rewards. DocFinQA covers financial document QA, FinDeepResearch covers investment research reports, and the DS-1000 subset covers basic data processing, plotting and machine-learning library use. DS-1000 source-family deduplication, execution qualification and training splits remain pending; the new training experiment has not started.

Settings

  • Base model: Qwen3.5-4B-Base. S0 and S1 start independently from the same weights; paired DAPO runs use the same starting checkpoint.
  • Teacher Model: Qwen3.8-27B generates demonstration trajectories for SFT.
  • Original data and evaluation: Original task identities are shared wherever training is applied. All nine candidates use the same frozen validation and testing sets, tool conditions and grader versions. Only validation selects checkpoints.
  • Additional data: Every S1 descendant shares the same SFT additions; every R1 candidate shares the same separate DAPO additions. These pools are not regenerated per candidate. The additional-task pools are not yet frozen.

Harness

Harness elementCore contentImplementation in this project
Context management提示工程、Agent 状态栏、上下文压缩、Agent Skills
  • Prompt engineering: Task environments supply system prompts, questions, output requirements and allowed tools.
  • Agent status panel: H1 (the runtime configuration with checklist, constraint checks, verification and bounded correction) stores a checklist with set_checklist and restates completion markers after observations as text.
  • Context compression: - (No history summary/compression; messages are append-only and new tool results are length-capped.)
  • Agent Skills: - (No skill-package loading or invocation in the model runtime.)
Context management across sessions用户记忆、RAG、结构化索引、智能体化 RAG
  • User memory: - (Attempts initialize independently; no cross-session user-memory store.)
  • RAG: DocFinQA retrieves evidence from the assigned report for the current task; no user-memory storage.
  • Structured indexing: Numbered report chunks use a BM25 index and chunk_id-based neighboring reads; no cross-session personal-knowledge index.
  • Agentic RAG: The model can search, read and calculate repeatedly within a task. Cross-session updates are - (no memory-write/update protocol).
Tool interfaces and constraints工具分类、权限控制、MCP 标准、主动工具发现
  • Tool categories: Task environments register allowlists and JSON argument formats; only known tools are dispatched.
  • Access control: H1 checks arguments and rules before declared writes. The existing v2 Python adapter has bubblewrap isolation, read-only mounts, no network and time/memory limits; DS-1000 is not yet integrated.
  • MCP standard: - (Direct function-tool registration; no MCP integration.)
  • Active tool discovery: - (Tool lists are fixed at attempt initialization; no dynamic search or loading.)
Verification and correctionCoding Agent 的 Harness、测试驱动、代码化规则
  • Coding Agent Harness: The model→tool→real observation→model loop and trajectory recording exist; DS-1000 code-completion integration is incomplete.
  • Test-driven execution: - (Offline tests and graders exist; no runtime test-first coding workflow.)
  • Codified rules: H1 checks checklist completion, environment requirements and result grounding. Errors include valid-call examples; repeated calls get hints; rejected completion permits bounded correction.
