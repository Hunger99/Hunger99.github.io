摘要

本项目把 4B 底座模型 Qwen3.5-4B-Base 后训练成会调用工具的金融 agent：它查询行情、宏观序列和公司财报，在 Python 沙箱里计算，并回答多步问题。官方后训练的 Qwen3.5-4B 已经能做对我们早先行情检索开发题的 84.7%，所以我们构建了一套更难的离线数据集，共 3,148 道题（训练 2,350 道、开发 200 道、测试 598 道）。其中 2,850 道参照公开 benchmark FinSearchComp 在固定数据快照上生成，答案由程序计算并由另一套独立实现复核；其余是 98 道 FinSearchComp 题和 200 道针对整份年报的 DocFinQA 题。教师（更大的模型 Qwen3.8-27B）在 agent harness（包在模型外面、提供工具并检查答案的代码）中做两档难度的行情训练题和读年报的题，每次做题存成一条轨迹，即消息、工具调用和工具结果的完整记录。过滤后的这些轨迹，连同过滤后的财富管理和机器学习轨迹，以及取自金融与通用数据 1:1 混合数据的 2,000 条样本，用多轮 agent SFT（监督微调，用带标准答案的样本继续训练）训练 4B 模型。在 300 道来自留出股票和更晚时段的行情测试题上，SFT 模型做对 87.3%，官方 Qwen3.5-4B 为 57.7%，起点模型为 16.7%，教师为 94.7%。在 DocFinQA 上它做对 53.0%，与官方模型持平，比第一次 SFT 高 14.0 分，第一次 SFT 的数据里没有读年报的轨迹。项目以 SFT 检查点为起点，用 DAPO 做强化学习；这些已报告的 SFT 结果对应历史数据批次，下文的数据架构将程序扩充与 Claude 探索分开，并采用共同审查。

数据架构用程序生成扩充已知薄弱能力，用 Claude 生成探索尚未覆盖的任务结构；两路共用独立核验和强制 Claude 审查。题目合格、示范合格与训练带来提升分别验收。

固定来源与四类划分，让方案选择和最终测试各自独立

  • Source inventory：每道题记录数据快照、实体、日期、父题、题族与生成方式；原题重叠和年报重叠分别统计，避免把已见年报上的新问题称作新年报。
  • Four-way split：训练集提供学习样本，校准集固定格式与难度测量，开发集选择配比和检查点，冻结测试集只报告最终方案；派生题继承来源划分，测试题及其答案不进入生成反馈。
  • Failure analysis：训练与校准上的有效失败揭示缺失操作、不稳定决策和未覆盖约束；工具故障与题目错误单独诊断，避免把运行问题当作需要扩充的难题。

两条支线分别练习已有薄弱点和探索缺失的任务结构

  • Program generation + Claude review：带种子的程序在已验证题族内改变实体、日期、约束和相互依赖的计算，为模型表现不稳定或反复做错的合理题提供可复现练习，也生成较简单的递进版本。
  • Claude generation + Claude review：生成对话根据能力缺口、可用数据和工具合同提出新题族及具体题目，并明确规则；改写已有题面或增加字数不自动算覆盖新能力。
  • Claude requests：v2 客户端配置为将两路的 Claude 请求统一发往 CLIProxyAPI 的原生 Messages 接口，使用自定义提示，各角色的上下文分开。请求指定 Opus 5.5，出题用 Extra High 推理强度，盲解、对抗审查与轨迹审查用 Medium；调用记录将实际返回的模型与请求的推理强度绑定至结果，便于追查审查依据。
  • Trusted task adapters：适配器把结构化题目交给工具和独立答案程序检查；行情适配器处理窗口选择、用反向市场头寸抵消部分波动的对冲计算及计费持仓，有限整数分配合同规定每个账户可以买几手、各自的限制和共同预算。超出合同的提案先隔离，补齐数据、工具与验证器后再接入，模型生成的验证代码不能直接充当标准。
  • Family promotion：Claude 探索的题族成熟后可转成经验证的程序模板扩充；题族最初由谁设计、当前实例由谁生成分别记录，每个新实例仍接受共同审查。

独立计算与 Claude 审查分别检查不同错误

  • Rules and tool execution：模型审查之前先检查格式、单位、重复和划分边界；分开的计算实现重新得到标准答案，参考解法再通过实际工具执行，避免题目依赖学生无法取得的依据。
  • Blind solution：新的 Claude 对话只看学生可见的题目、材料和工具约定，并写出解法；解法在相同 CPU 工具沙箱中执行，输出通过独立评分后才进入对抗审查。
  • Adversarial review：另一独立对话检查题目与参考解法是否存在歧义、矛盾、不可得信息、单位错误、未来信息和评分漏洞；每个收录实例都要有带依据的通过结论，缺失、失败或超预算的审查保持未决。分开对话不能保证同一模型不会重复相同误解。

实测成功模式决定题目的训练用途

  • SFT candidates：教师成功的一次尝试只产生示范候选，通过该轨迹的检查与审查后才进入监督微调（SFT），让学生模仿可靠过程。
  • Demonstration review：每条收录的 SFT 示范还要检查成功读取、计算依据、被接受的最终交卷及实际解题方法，并通过 Claude 审查；被驳回动作留在上下文，其 token 不计入模仿损失，使正确恢复的过程可以保留。
  • RL candidates：当前学生多次回答有对有错的题，能为 DAPO 提供组内奖励差异；全错题先诊断、补可靠示范或递进练习，全对题可以维持已有能力。有限次试答估计当前表现，不能证明训练收益。
  • Deduplication and reuse：跨训练和保留池核对原题及相关来源实例；新的 RL 题池排除上一批 SFT 已用题。在线 RL 奖励继续由程序计算，不为每条探索轨迹增加 Claude 判官。

按合格题目配比，并固定所有实际训练输入

  • Accepted-instance mixture：两路比例按共同审查通过的独立题目计算，不按生成尝试或同题多条轨迹计算；合格数量不足时停止发布，不用重复或不合格题补额，SFT token 和有效 RL 回答组另行统计。
  • Cost control：规则先淘汰明显错误，内容和版本完全匹配的审查可用缓存；费用涵盖 Claude 生成、两路题目审查、SFT 轨迹审查与失败尝试，共同上限在发请求前预留最坏费用，中断或无法计费的调用会阻止继续花费。
  • Release contract：代码、快照、提示、模型身份、独立参考、审查、题目 ID、分词器和损失掩码共同绑定数据版本；CPU 诊断通过和模拟输出不能批准训练。新一轮 SFT 使用基础模型、新打包数据和新输出目录，RL 再使用其产出的检查点及新测量。
两条生成支线，共同强制审查题目与示范分别验收
数据快照 → 划分 → 程序出题 → 计算答案 → 独立复核 → 组成数据集

已报告模型的原程序题库使用固定快照和可执行的参考答案。

数据快照把数据固定下来，程序才能计算并复核每个答案

  • SQLite snapshot：一个数据库文件存放 565 只证券的日线和 35,727 条拆股分红、68 条 FRED 宏观序列，以及 516 家公司的 SEC XBRL 财报（机器可读的公司财务报告）。在线数据会变，只有固定快照才能让程序算出每个答案并给每道题判分。
  • Point-in-time vintage：快照固定 FRED 在截止日或最新存储版本中的数值，不能还原每个更早决策日当时已知的版本，因此这些任务不构成满足历史信息可得条件的回测。

划分让测试的实体和时段不进训练

  • Entity split：股票代码的哈希把每只股票分到训练、开发或测试（约 70/10/20），财报题跟着公司走，所以行情测试集测的是模型没见过的公司。
  • Temporal split：指数、ETF（像股票一样交易的基金）、汇率和 FRED 序列按时间分成训练 2000–2016、开发 2017–2019、测试 2020 年起，所以行情测试集测的是训练时间窗之后的时段。
  • Limit of the split：开发集只有 47 只股票、测试集 99 只，标普 500 成分股用的是 2026 年的名单，所以只含存续到那一年的公司。

原程序生成批次复用 FinSearchComp 的操作，并增加难题档

  • Need for harder tasks：官方 Qwen3.5-4B 在财富管理 14 个题型中的 11 个上已接近满分，这些题主要考按规矩调用工具，所以项目需要官方模型也做不好的题。
  • Operations from FinSearchComp：逐题标注 FinSearchComp 的 T2、T3 题时，不复权价格、某日之后第 N 个交易日、阈值扫描、区间极值、按月重采样、最大回撤、滚动标准差反复出现，生成器据此定题型，因为这个 benchmark 的难度来自取很多期数据、复权、换算单位和多步汇总。
  • Original tier：生成器抽取实体和时间窗，构建 17 个难度 1–3 的题型，每个题型 200 道训练题、20 道开发题、30 道测试题，这样训练能单独练到上面这些操作。
  • Hard tier：教师在原有一档开发题上做对 99.7%，因此生成器增加 8 个难度 4–5 的组合题型探索更高难度；学生能否获得强化学习信号还需单独测量。组合题把多个操作串起来，一步出错就答错，难度来自步骤和约定，而不是生僻的数据。
  • One round of hardening：生成器重写教师在开发集上做对至少 95% 的 5 个难题档题型：只给公司名、改用标准术语、增加键，教师在这些题上从 98/100 降到 93/100，因为这一档需要教师也会做错的题。这一步只做一次，因为反复修改就等于在开发集上调题目。

计算答案让每道题都有程序能核对的标准答案

  • Computed answers：生成器从快照算出每道题的标准答案，并去掉容易误判的候选，比如答案落在四舍五入边界附近或日子贴近阈值的题，这样分数不取决于四舍五入的边界。
  • Key-based grading：判分程序把标准答案拆成键（容差内的数值、日期、文本或集合），每个键都在最终答案中正确出现才算通过，所以分数不需要模型裁判，也能重算。计数键仍可能被答案里别处的同一个小整数碰上。

独立复核检查答案和工具

  • Independent verification：另一套 SQL 加 Python 的实现从题目参数重算答案，两档全部一致。比较两套实现可以发现差异，但共享的假设或错误仍可能漏过这项检查。
  • Golden policy：标准解策略只用工具（一次 Python 加 finish），经过与模型相同的循环、验证和判分，做对每一道题，说明工具足以解每道题。

数据集共 3,148 题，来源和题型按开发集结果选定

  • Composition：题库固定训练 2,350 题、开发 200 题、测试 598 题，共 3,148 题；测试来源见数据一节。开发集用于方案选择，冻结测试集报告选定方案的结果。
  • Training file：训练文件含 7 个难题档题型各 250 题和 rolling_vol、extreme_period、xbrl_ratio 各 200 题，共 2,350 题。它去掉第 8 个难题档题型 div_event_study，因为官方模型在它的开发题上做对 19/20，没有空间显示提升；它保留原有一档中官方做得最差的 3 个题型（2/20、14/20、14/20）。SFT 模型还用了原有一档另外 14 个题型的轨迹，比这 2,350 题多 2,800 题。
  • Development and market-data test files：两个文件使用相同题型，并沿用前述实体与时间划分；测试题不按模型的答题对错筛选，让各模型在同一批固定题目上比较。
  • FinSearchComp file：在 203 道 Global T2、T3 题中，这个文件保留快照算出的值与官方答案在容差内一致的 98 题，这样分数不依赖与官方答案不一致的快照值。
上下文管理 工具接口与约束 验证与纠正

本工作的 harness 分为三部分：上下文管理、工具接口与约束、验证与纠正。下面描述的是第 3 版，用于行情和 DocFinQA 任务；财富管理、机器学习和 t6_report_gate 任务用第 2 版，它会把较早的工具结果截成摘要。

上下文管理

  • System prompt：Harness 用一条消息开始每个任务，写明模型的角色、任务的规则和工具用法。
  • Append-only context：Harness 发出消息后不再改动，所以每次请求的消息都是下一次请求和所存轨迹的前缀。这样所存轨迹就是模型每一步看到的内容，SFT 和 RL 用的序列与采样一致。
  • Tool-result cap：工具返回时，harness 把每个结果截到 8,000 字符，并附一句说明如何少取，比如翻下一页或缩短日期区间。行情工具一页的结果都在 7,500 字符以内，read_chunk 带相邻段落约 7,100 字符，都低于这个上限，所以模型不会拿到被截断的 JSON。
  • Checklist（set_checklist）：模型把请求的步骤写进清单并勾选，harness 在每次工具返回后复述清单，一个任务最多调用 20 次。这主要减少漏做子任务。
  • Step budget：Harness 只把任务轮计入 100 步上限；只维护清单的轮、含被驳回 finish 的轮及其后 10 轮都不计入，总轮数硬上限为 142。清单和重做是 harness 自己加的动作，计入步数时会在长任务上用完步数。
  • Thinking-preserving chat template：改过的 Qwen3.5 对话模板（把消息渲染成模型输入的规则）保留第一条用户消息之后每个助手轮的思考。在原模板下，nudge 是一条用户消息，它让之前的思考从下一个提示中消失，所存轨迹也就不再是模型看到的内容。
  • Token-level logging：Harness 记录每轮的提示 token 数、采样的 token 和它们的 log 概率，以及 prefix_ok，这个标记说明本轮提示是否以上一轮的提示和生成内容开头。这样 RL 可以直接用采样时的 token 和概率，不必再打分一遍，这个标记也能查出渲染得与采样时不同的轮。

工具接口与约束

  • Function calling：Harness 用 JSON Schema（一种描述结构化数据的标准格式）向模型描述每个工具的名称和参数，模型按原生函数调用格式调用工具。
  • Tool sets：行情环境提供 11 个工具，财富管理 12 个，机器学习 5 个，DocFinQA 4 个，t6_report_gate（第 2 版）14 个，都含结束任务并交答案的 finish；完整 harness 另加 set_checklist。
  • BM25 two-step retrieval：BM25 是关键词排序算法：查询词在一段里出现得越多、在其他段里越少见，这一段得分越高；harness 只用它，没有向量检索或重排序。检索财富管理的基金招募说明书知识库时，最多返回 10 段的编号、标题和开头文字，模型再按编号读全文。DocFinQA 把 10-K 切成 1,500 字符的段落，相邻两段重叠 200 字符，检索只返回约 240 字符的摘要，read_chunk 才给全文。
  • Sandbox（run_python）：Harness 在 bubblewrap（隔离进程的 Linux 工具）里运行模型写的代码，没有网络，临时目录之外的文件系统只读，限 30 秒、3 GiB。
  • Constraints：写操作执行前，代码按工具 Schema 和业务规则检查它的参数，拒绝违规操作且不执行，并把原因返回模型，这主要减少违反业务规则和参数错误。

验证与纠正

  • Answer verification：模型调用 finish 时，harness 检查答案中的数在工具结果或请求中有依据、清单全部完成、环境自己的检查通过；在行情题上，工具结果中的数经千、百万、十亿或百分比换算并按答案的小数位取整后相等，就算有依据。所以单位换算能通过，心算或凭记忆写出的数会被驳回。
  • Rejection limit：Harness 在一个任务里最多驳回 2 次 finish，下一次不经验证就接受。
  • Correction messages：Harness 在驳回 finish 后返回未通过的检查项，在工具报错后返回一个正确调用的示例，这主要减少陷入循环和步数用尽。
  • Loop hint：Harness 在第 3 次相同调用时提示模型换思路。
  • Nudge：回复没有调用工具时，harness 追加一条提醒。
  • Packing：构建器排除 48 条超过各自 token 上限的轨迹，以及 7 条会使对话模板丢失历史思考的多用户消息轨迹；再用保留思考的对话模板渲染 32,768 token 以内的行情和 DocFinQA 轨迹，用 Qwen3.5 自带的模板渲染 32,768 token 以内的 t6_report_gate 轨迹和 16,384 token 以内的财富管理和机器学习轨迹，再把 14,486 条样本拼成 2,830 条不超过 32,768 token 的序列，这样短样本能填满每条序列的 token 预算，每步 12 条序列能训练约 61 条样本。行情上限取 32,768，是因为 xbrl_ratio 轨迹的中位长度有 17,661 token，按 16,384 截会丢掉这个题型一半以上。
  • Settings：训练微调 Qwen3.5-4B-Base 的全部参数，2 个 epoch（把数据过两遍）、472 步，用 6 张 GPU，学习率 1e-5，沿余弦曲线下降。从 Base 模型出发，模型在预训练之后学到的东西就都只来自本项目的数据。
  • Loss：训练最小化模型下一个 token 的预测与标签之间的交叉熵，也就是下一 token 预测的标准损失 \(\mathcal{L} = -\frac{1}{N}\sum_{t:\, y_t \neq -100} \log p_\theta(y_t \mid x_{<t})\)，其中 \(x_{<t}\) 是位置 \(t\) 之前的序列，\(\theta\) 是模型权重，\(N\) 是带标签的 token 数，所以模型逐 token 复现带标签的轮。训练只在带标签的位置分块计算损失，数值和梯度都不变，因为长序列每个位置对全词表的打分放不进显存。
  • Labels：需要模型学习的位置，标签就是该 token 本身；其余位置为 −100，损失会忽略。标签覆盖轨迹助手轮的思考、文本和工具调用，因为模型之后运行的对话模板会把历史思考放进上下文；标签屏蔽系统、用户和工具轮，因为工具输出由工具产生。
  • Masked turns：行情和 DocFinQA 轨迹屏蔽招来 nudge 的回复和含被驳回调用的轮，但把它们留在上下文里，因为这些轮计损失等于教模型先交错答案，而之后的改正照样能学；t6_report_gate 轨迹同样屏蔽被驳回的轮。财富管理和机器学习轨迹的被驳回轮仍计损失。带 nudge 的财富管理、机器学习和 t6_report_gate 轨迹被整条丢掉。
  • Malformed calls：建数据的程序还屏蔽调用格式错误的轮，比如不存在的工具名，因为这些轮计损失就是教模型写错名字。
  • Sample boundaries：每个批次都告诉模型同一条序列里每个样本的起止位置，否则 Qwen3.5 的线性注意力层（沿序列传递状态的一种注意力）会把一个样本泄漏到下一个。加上边界后，每 token 损失的最大差异从 6.3 降到 0.13，属于数值噪声。

分数与比较

  • Success rate：这个分数统计任务集 \(T\) 中通过的比例，任务 \(t\) 通过时 \(s_t = 1\)，所以只有整个任务做对才得分。\[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • Paired bootstrap：这项比较按题相减两个模型的结果，\(a_i\)、\(b_i\) 做对为 100、做错为 0，95% 区间来自对 \(n\) 道题的 10,000 次重抽。配对去掉了题目难度的差异，区间因此变窄；每道测试题只跑 1 次，所以区间只计入题目抽样的误差。\[\Delta = \frac{1}{n}\sum_{i=1}^{n}(b_i - a_i)\]

金融问答与通用能力

  • 金融分：打分程序取最后一个 "Answer:" 之后的第一个数，与标准答案相差 1% 以内算对，百分数和小数两种写法都认。所有模型用同一个不套对话模板、带 3 个示例的提示，因为起点模型没有针对对话格式训练过，这样分数才可比。其中 \(D\) 是题目集合，\(y_i\) 是标准答案，\(\hat{y}_i\) 是回答，\(\tau_i = 0.01|y_i|\)，\(y_i = 0\) 时为 0.005。\[A_{\text{fin}} = \frac{100}{|D|}\sum_{i \in D}\mathbf{1}\Big[\min_{k \in \{1,\,100,\,0.01\}}|k\hat{y}_i - y_i| \le \tau_i\Big]\]
  • MMLU：打分程序在题目集合 \(Q\) 上，把提示 \(x_q\) 下概率最大的选项 \(o\) 与正确选项 \(o^{*}_q\) 比较。比较选项概率不依赖生成格式，所以起点模型和 SFT 模型可比；去掉四个经济和会计科目，因为金融训练会抬高它们，掩盖别处的下降。\[A_{\text{MMLU}} = \frac{100}{|Q|}\sum_{q \in Q}\mathbf{1}\Big[\arg\max_{o}\log p(o \mid x_q) = o^{*}_q\Big]\]
  • GSM8K：打分程序比较回答中的最后一个数 \(\hat{a}_q\) 和标准答案 \(a_q\)，这说明多步算术推理在财报格式之外有没有保住。所有模型用同一提示，含 5 道示例题，不用对话模板，与金融分相同。\[A_{\text{GSM}} = \frac{100}{|Q|}\sum_{q \in Q}\mathbf{1}[\hat{a}_q = a_q]\]
  • IFEval：打分程序只在回答满足提示集合 \(P\) 中一条提示的所有可检查指令 \(I_p\)（如字数上限或 JSON 输出）时才计分，指令 \(j\) 成立时 \(f_{p,j}=1\)，这测的正是 agent 必须具备的按规则和格式作答的能力。所有模型都通过允许先推理的对话模板作答，打分程序读推理之后的文字。起点模型用 Qwen3.5 原生模板加停止规则，不用模板时它只有 37.7 分。\[A_{\text{IF}} = \frac{100}{|P|}\sum_{p \in P}\prod_{j \in I_p} f_{p,j}\]

Agent 任务

  • 行情测试集和 FinSearchComp：判分程序按离线数据集一环的 key-based grading 判分，FinSearchComp 用每题写明的容差。
  • DocFinQA：判分程序取答案中的最后一个数，与标准答案相差 1% 以内算通过，百分数和小数两种写法都认，是非题要写出同一个词，这样得到的分数能与外部结果比较。
  • State comparison（财富管理）：判分程序把最终持仓、现金和交易记录与标准状态比较，并把答案中的关键数值按容差比较（金额 ±0.01 美元，比例 ±0.1 个百分点）。对规则禁止的任务，它检查被禁止的交易没有执行、答案指出了规则，因为交易和答案都对才算完成任务。
  • AUC 和 \(R^2\) 门槛（机器学习）：AUC 衡量排序质量，0.5 相当于随机、1 为完美；\(R^2\) 衡量模型解释的目标方差比例。判分程序要求提交模型，且它在隐藏测试表上不低于生成数据的模型减 0.015 AUC 或减 0.03 \(R^2\)。这个门槛要求把数据处理做对：在开发集上，固定流程对偏态列取对数时通过 20/20 题，不取对数时只过 1 题。
  • pass@1 和 pass@4：打分程序在 \(T_4\) 上算这两个分数，\(T_4\) 是有 4 次有效尝试的开发集题目，题 \(t\) 的 \(n_t\) 次有效尝试中有 \(c_t\) 次通过。\[P_1 = \frac{100}{|T_4|}\sum_{t \in T_4}\frac{c_t}{n_t}\] \[P_4 = \frac{100}{|T_4|}\sum_{t \in T_4}\mathbf{1}[c_t \ge 1]\]

选题正在进行，训练尚未开始，这里的训练取值都是计划值。DAPO 是下一步要用的强化学习（RL）方法。它建立在 GRPO 之上，这种方法对每道题采样一组尝试，按组内相对表现给每次尝试打分。DAPO 加上下面前四项改动，并去掉 KL 惩罚，这是把模型拉近自身冻结副本的一项额外损失。训练将用 verl 自带的 DAPO 实现，从上面的 SFT 模型出发。

  • Clip-Higher：训练限制一次更新对 token 概率的改变：新旧概率之比最多下降 0.2、最多上升 0.28。
  • Dynamic Sampling：verl 的训练程序丢掉 8 次尝试判分全相同（全对或全错）的组，不看长度，并为它补发 2 道题，因为这样的组没有对错之差，留下只会训练长度信号。补题没有上限，所以被丢的组越多，这一步越慢。
  • Token-level loss：token-mean 直接对所有 token 平均损失，所以长回答里每个 token 的权重不被摊薄。
  • Overlong reward shaping：verl 的 DAPO reward manager 在判分 \(r\) 上加长度奖励：长度 \(L\) 不超过 \(L_s\) 时为 0，之后线性降到预算 \(L_{\max}\) 处的 −1。写满预算的尝试一定判错，所以总奖励 −2，它也计损失。这里 \(L\) 含工具结果的 token 数，缓冲 \(L_c = 4{,}096\)，\(L_s = L_{\max} - L_c = 24{,}576\)；预算 \(L_{\max} = 28{,}672\) 加 4,096 token 的提示正好等于 32,768 token 的 SFT 序列。\[R = r + \min\Big(-\frac{L - L_s}{L_c},\ 0\Big)\]
  • Reward：判分程序通过给 +1、否则给 −1，与 DAPO 相同。若用 0/1，同样的扣分相对于对错之差会重一倍。
  • No KL：训练不加 KL 惩罚，因为长推理时模型本来就会明显偏离起点；这也省下这个副本的显存和前向计算。
  • Task selection：SFT 模型对题池中每道题做 8 遍，选题去掉 0/8 的题，保留 1–7/8 的题，8/8 的题留 10%，因为所有尝试判分相同的题给不了组内比较任何信息。留下的 10% 让模型继续练一些已经做对的题。如果留下的题更多，再按题型分层、按各题型的占比抽样，把平均每个题型控制在 93.9 题，这个题量大体决定一次运行过这些题的遍数。训练中模型在变，选中的题也可能变成全对或全错，所以动态采样在每一步继续丢掉这样的组。
  • Task pool：题池的行情部分是新生成的题，10 个题型各 200 题，没有一道重复 SFT 的训练题、开发题或测试题。在 2 道 DocFinQA 题上的试跑通过时，再加 200 道 DocFinQA 训练题作第 11 个题型，否则 RL 没有信号维持 SFT 模型读文档的能力。
  • Settings：用 8 张 GPU 时，每步取 128 道题、每题 8 次尝试，mini-batch 为 32 道题，所以每步更新 4 次；共 21 步，学习率 1e-6，一次尝试最多 30 个任务轮。

尚未开始 最终的 DAPO 模型将按 SFT 评测一环的规则跑行情、FinSearchComp、DocFinQA、开发集、财富管理、机器学习和通用能力这些任务集，与起点模型、教师和 SFT 模型比较，另加三项。

  • Strict grading：严格判分给行情、FinSearchComp 和开发集的答案加四条规则，全部满足时 \(r_t = 1\)。答案在日期之外最多有 50 个数字。答案最多有 40 个不同日期。每个数值键都要在日期之外出现。有候选的题上，首先点名的公司要正确，其后每个公司键都要紧跟它的数值。原判分只要键出现在答案任何位置就算对：一次审计中，不知道任何参考值、只复述题面加数值网格的答案通过了 209/939 道 RL 训练题，所以只看原判分，RL 的提升不可信。\[S_{\text{strict}} = \frac{100}{|T|}\sum_{t \in T} s_t\, r_t\]
  • Reworded test：换措辞把 300 道行情测试题用新的措辞重写，参数和答案不变，与同题型训练题的 5-gram 重合从 0.77–0.99 降到 0.10–0.32，所以分数变化说明成绩有多依赖措辞。\[\Delta_{\text{reword}} = S_{\text{reworded}} - S_{\text{original}}\]
  • Paired gain over the SFT model：这项比较在每道题上取 SFT 模型的 \(a_i\) 和最终 DAPO 模型的 \(b_i\)，用 SFT 评测一环的 paired bootstrap。
