摘要

本项目使用 DocFinQA、FinSearchComp、IFEval、FinDeepResearch 和 MLE-bench 项目子集，比较 Qwen3.5-4B-Base 的九个训练设置。监督微调（SFT）学习经过验证的示范，DAPO 从工具辅助试答与任务专属奖励中学习。FinSearchComp 的扩充先获取真实公开金融资料，再由程序或 Claude 基于证据出新题；两路共用独立计算、工具执行、盲解与对抗审查。所有设置保留相同原题队列及评测协议，以比较在 SFT、DAPO 或两个阶段增加 FinSearchComp 题目的作用。FinDeepResearch 和 MLE-bench 在此保留原始基准任务的定义，额外任务的构造方法不在本页展开。新一轮训练实验尚未开始。

Task format 描述期望的求解形式：一次回答，或多次模型／工具交互后提交最终产物的智能体任务，不按最初有几次用户请求判断。给齐材料的 SFT 视图可省去检索，检索阶段则保留多轮任务。示例经过简写或改写，中文为译文，完整要求见对应来源。

各数据集保留自己的输出与评分含义；公司报告的内容分、机器学习竞赛分数与问答准确率分别报告。

本表定义原始基准。公开金融资料为新增 FinSearchComp 题目提供证据，资料本身不增加原始基准题数；自行编写的新题另记为派生／合成任务。资料获取与出题步骤统一在方法管线中说明。

Settings

  • Base model: Qwen3.5-4B-Base。S0、S1 分别从相同权重独立开始；配对 DAPO 实验使用相同的起始检查点。
  • 原题与评测: 执行训练的设置共用相同原题身份；九组共用同一份冻结的验证集和测试集，以及相同的工具条件和评分器版本。仅使用验证集选择检查点。
  • 新增数据: 所有 S1 后续设置共用同一份 FinSearchComp SFT 新增题；所有 R1 设置共用另一份固定的 DAPO 新增题，不为不同候选重新生成。
  • 训练控制: 同一训练阶段内，有无新增题的配对实验使用相同训练配方及 token／计算预算，比较的变量是是否加入新增训练数据。

方法管线

点击下面的环节查看它做什么。

→ → → → → → →
规范报告 → 任务约束 → 来源隔离 → 冻结题目池

每份财报只引用一个原始版本

  • Canonicalization: 入口按注册主体与财年结束日期归并 DocFinQA 报告，依据来源质量选择一份原文，并保留其他版本及来源哈希，避免等价报告被当成不同材料。
  • Evidence retention: 选择后的检查隔离丢失必要运算依据的问题；检查不改写报告，也不依据模型成绩选择报告版本。
  • Original filing semantics: 金融生成前先将指标含义、合并报告上下文、期间、单位和正负号绑定到原始申报；负债减项须拒收或隔离，不能取绝对值修成余额，来源通过也不等于题目合格。

共同外层接口保留各任务的原生输出

  • Task adapter: 计划中的五数据集接口将来源身份与输入文件、隔离的工具轨迹、提交产物及各数据集评分结果绑定起来；共用这份外层记录，让同一运行器管理不同任务，同时保留报告写作和机器学习工程的任务形式。
  • Qualification: 新适配器须先通过证据访问、原生评分、产物格式与评分端隔离检查，再准入任务；数据集表定义任务输出和指标，共同数据控制使各候选使用一致的原题及评测条件。

先核对来源身份，再抽取题目

  • Decontamination: 划分器跨集合核对报告身份、规范化题面、题目派生关系及金融答案支持期间；身份未识别的报告留在合格题目池之外。
  • Stratification: DocFinQA 保留官方划分归属，按数值／布尔类别比例各保留一半；FinSearchComp 与 IFEval 使用确定性的类别分层项目划分，以保留类别覆盖及足够的测试题。

一个版本服务所有模型设置

  • Immutable inputs: 现有原题 ID、原始文本、规范报告与评分器绑定到冻结版本；新增队列及适配器通过资格核验后才并入共同版本，候选设置规定共同对照条件。
  • Reserved evaluation: 合成验证、测试题使用隔离的答案支持来源并独立审查；不能用重复题或未审查候选填补验收配额。
公开来源 → 原始证据缓存 → 合格来源库

FinSearchComp 扩充先取得真实金融资料，原文与观测值作为证据交给下一阶段出新题。当前获取路径覆盖已有 SEC／FRED 来源，新增网站须完成相应的接入核验。

公开材料提供可核验的事实

  • Source selection: 来源库按题型及资料用途选择公司披露与官方经济观测；已有输入包括 SEC 申报和 FRED 序列。新增提供方须先核实来源身份、访问条件和证据取得路径，再用于出题。
  • Original documents: 获取过程定位原始申报或序列响应，保留原材料及来源记录；公司报告、披露转载与派生题保留关联，避免重复材料增加独立题数。

先保存原始证据，再规范事实字段

  • Source cache: 下载材料与复用快照保留来源身份和版本；规范化事实关联原始披露或序列，并记录主体、报告期间及单位，让审查者核对计算依据，而非信任生成文字。
  • Time convention: 每题使用明确的冻结快照；今天取得或修订的观测值，不自动代表过去决策时点已经知道的信息。历史可得信息题与实时行情题须另行核实日期、数据版本及提供方权限。

来源检查保护共同评测队列

  • Evidence checks: 生成前核对原始申报中的指标含义、合并报告上下文、期间、单位和正负号；支持缺失或有歧义时保留待审，不要求出题模型自行补造事实。
  • Source isolation: 来源库排除受保护的评测支持材料，将合格事实绑定到声明的 SFT、DAPO、验证或测试用途；两条出题支线共用这份已核对来源库。原始基准定义保留在数据集表中。
程序支线 Claude 支线 编译与合并 逐次 API 计量

本阶段从已核对的公开资料库构造 FinSearchComp 新题。程序扩充现有合同支持的薄弱题族，Claude 在来源和任务合同内探索新的组合；两路都属于基于真实材料自行出题，之后进入相同审查关卡。导入已有问答是另一种数据接入操作，不属于本阶段的生成步骤。

程序扩展可复现的薄弱题型

  • Financial diagnostics: 生成器先区分金额、公司、时期、单位错误与格式、来源标识错误，再决定强化的能力，避免将格式失败当成金融推理难题。
  • Programmatic generation: 模板在固定来源内改变事实与依赖关系，扩展可重复的薄弱题型。强化金融编译器先筛选完整候选集合，唯一定位合格公司，再据选择结果决定比较公司；固定名字不能泄露答案。

Claude 基于固定来源提出支持的任务

  • Source-bound generation: Opus 5.5 以 Extra High 强度从已审来源库选择结构化计划；宿主编译器生成学习者任务并计算参考答案，作者自由叙述与私有答案不成为权威题面。
  • Coverage: 当前金融合同支持 SEC／FRED 检索、比较与依赖计算；新增任务结构须有可取得的来源证据和可执行验证器，超出支持合同的提案保留隔离。

两条支线都产生绑定来源的新候选身份

  • Canonical task: 最新强化金融合同统一节点及输出标签，并从类型字段渲染筛选、排序、比较和单位规则；实质改题产生新任务身份，旧审查随之失效。
  • Candidate inventory: 同一份不可变语义索引跨两条支线归并支持的等价任务，并固定其 SFT、DAPO、验证或测试用途。重复别名保留历史，但在受守卫入口不能重复占配额或重复付费审查。

计量在每次原生请求前后执行

  • Request sequence: 宿主绑定完整提示，在共享锁内预留所有在途请求的最坏费用，再经 CLIProxyAPI 发出独立原生 Messages 对话。出题按保守配置的输入上界预留，盲解与对抗审查使用经过校准的原生输入 token 计数；随后保存原始响应，并将实际 token 用量结算到追加式账本。出题用 Extra High，盲解和对抗审查用 Medium。
  • Failure handling: 失败和重试都消耗同一授权，缺失用量、输入改变或超出已绑定上界即停止后续调用。代理转发明确的自定义提示，OAuth 身份元数据与计费字段仍会保留，不宣称是零附加输入的直接 API。
  • Execution scope: 独立候选通过来源、规范题索引和额度检查后才可并发。改动后的任务合同须有对应的新审查，前版验收不直接授予正式训练资格。
来源与参考答案 真实工具执行 盲解与对抗审查 题目准入

来源含义与独立答案必须一致

  • Financial reference: 独立算术实现核对答案、单位、来源期间与舍入规则；候选筛选须完整、有效且唯一，并列、无依据事实、依赖遗漏和零分母均拒收。
  • Semantic deduplication: 有守卫的 typed 审查入口在付费审查前只接收索引中的规范任务；索引保留支持的经济含义与来源期间，忽略分支或修饰标签，但不证明任意文字和代数表达都已去重。

宿主实际执行来源读取与产物提交

  • Sandbox replay: 金融解法查询固定只读证据快照，并须与独立计算的参考答案一致；实际来源读取、程序与返回结果均保留，模型文字不能单独证明已执行。
  • Retrieval evidence: 宿主记录绑定真实查询、返回、代码与快照身份；真实“模型→检索→模型”检查已确认返回证据进入后续模型请求，干预实验另检查保留模型代码是否使用证据。这不能证明模型每个内部推理步骤，也不替代完整同模型允许／禁止工具配对实验。

独立模型角色还须通过可执行反查

  • Blind solve: 独立 Medium 对话只接收学习者任务及工具合同，不接收私有答案；宿主实际执行其程序，并对执行结果评分。
  • Adversarial review: 另一个独立 Medium 对话查找歧义、缺证据、单位、答案泄露与评分漏洞，其不同解法也须实际执行正确，不能仅凭一段看似合理的审查文字放行。
  • Evidence adjudication: 仅凭记忆提出的疑点，只有获得绑定到同题、同响应、同执行的独立来源证明后才可重新裁决；原始拒绝或未决记录保留，实质疑点未解决时继续隔离。

样例通过不等于训练数据集已发布

  • Version-bound checks: 每道准入的 FinSearchComp 题绑定确切的任务合同、来源事实、模型响应与已执行解法；题目或来源改变后须有匹配的新检查。题目质量、难度、示范及发布分别核验。
  • Production boundary: 语义索引守卫目前覆盖新的 typed 审查路径；旧 continuous、batch、graph、cycle 路径在正式使用前须接入同一守卫或统一路由。题目质量、难度、完整示范与最终数据发布分别核验。
保存实际试答 → 难度测量 → 示范准入

框架保存模型行为与真实工具返回

  • Recorded execution: 框架保留模型消息、工具调用、真实返回与完成状态；金融试答使用只读证据工具和受限 Python，Harness 部分说明上下文及纠错行为。
  • IFEval: 固定严格指令检查器仅评分其最终答案，金融证据要求不应用于纯指令回答。

本地教师与学生试答决定训练去向

  • Difficulty measurement: 教师与学生多次试答仅使用训练或校准题；较大的教师提供候选示范，学生成功与失败模式区分不稳定能力与需要诊断或补充 SFT 的任务。
  • DAPO signal: 同题回答组需要奖励差异才能区分较好的尝试；全对或全错不自动产生有效 DAPO 信号，封存测试结果不用于选择训练难度。

完整且有依据的示范另行准入

  • Trace qualification: 准入核对来源凭据、成功证据读取、工具格式、事实依据、单位与任务完成，再独立审查轨迹；旧轨迹不能在缺少匹配证明时换绑到其他来源或改写后的任务。
  • Training release: 合格题、合格示范和绑定分词器的打包数据分别产出；只有完整且经过审查的轨迹才进入精确 token、掩码和共同版本检查。

  • Phase assignment: 阶段依据每题还缺什么必要信息来确定，不按数据集名称或是否使用 Python 划分；未核验的材料视图保持待审。

第二阶段先检索缺失材料，再完成推理

  • Retrieval and reasoning: 第二阶段将使用题面缺少必要信息的任务，让模型检索获准来源，对齐实体、时期与单位后再推理作答。
  • State continuity: 同一训练作业将跨阶段保留优化器（参数更新状态）与学习率计划，并连同模型保存完整检查点；每个模型的第二阶段将承接自己的第一阶段状态。

仅核验后的助手行为参与损失

  • Loss masking: 已准入的助手推理、工具调用与最终答案参与监督；system、user 文本、工具返回和无效助手内容仅作上下文。完整轨迹保留原有掩码与分词器绑定，过长或无法精确调度时待审，不截断凑量。
  • Shared budget: 每个条件全程共用 6,553,600 个有效监督 token 和 100 次更新，初始每阶段各 3,276,800 token／50 次更新。token 数只核对监督暴露量，沿用现有损失求平均方式；初始阶段比例尚未经效果验证。
  • Launch gates: 新一轮 SFT 尚未开始；证据、方法审查、必要的实际配对探测、完整示范、固定合成池和精确预算检查全部通过后，五数据集共同训练入口才能放行。

  • Selection: 只有验证集用于选择检查点和混合配比；最终配对置信区间使用相同冻结测试，不反馈给出题器。

Harness

Harness 是围绕模型运行的一层程序：管理对话、执行声明的工具，把真实结果和纠错反馈交回模型。统一的环境接口按任务类型选择工具与评分规则。H1 是其中启用清单、约束检查、结果验证与有限纠错的配置；试答选用 H1 时，才启用这些附加控制。

上下文保留模型实际看到的内容

每次尝试从环境提示词和任务开始，随后只追加消息，不改写先前轮次；服务模板支持时，Qwen 保留先前的推理。新工具结果在产生时限制长度，默认上限为 8,000 字符，超出后给出截断提示；检索、文档读取和长列表通过分页或限定范围返回。运行配置分别限制任务轮次、清单更新、纠错轮次和单次回复长度；上下文溢出会结束尝试。

纠错反馈帮助修改，独立准入检查保存的结果

宿主把工具参数解析为 JSON，只分派已知工具。H1 在执行声明的写操作之前检查约束；H1 启用纠错时，已知工具执行报错附有效调用示例；重复相同调用时提示更换方法。收到 finish 后，H1 检查清单及该环境的证据或输出要求，并在有限次数内返回具体问题供模型纠正；用尽纠错次数后仍可能结束，因此结束状态本身不代表答对。

独立评分器检查保存的答案或提交文件。金融数字匹配只检查答案是否有结果支持，不能单独证明推理正确；实际来源查询记录和执行回放提供额外证据。题目合格、完整示范合格和训练准入分别检查。

合成数据的角色另走 Messages 路由

出题、盲解和对抗审查分别使用独立的新 API 请求，提示词由调用方明确提供。在原生代理请求发出前，客户端检查冻结的题目与来源范围及费用预留；出题按保守配置的输入上界预留，盲解与对抗审查使用经过校准的原生输入 token 计数。返回后把用量和失败尝试记入只追加的账本。盲解角色编写的代码交给宿主实际执行，API 文本请求本身不执行工具；对抗审查读取实际回放证据，不继承先前审查结论。
