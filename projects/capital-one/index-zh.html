在训练过的题型上，多轮 agent SFT 把 4B 模型从 16.7% 提升到 88.7%，超过官方 Qwen3.5-4B（57.7%）。在训练数据没有覆盖的长文档问答上，它仍低于官方模型。

摘要

本项目把 4B 底座模型 Qwen3.5-4B-Base 后训练成会调用工具的金融 agent：它查询行情、宏观序列和公司财报，在 Python 沙箱里计算，并回答多步问题。官方后训练的 Qwen3.5-4B 已经能做对我们早先行情检索开发题的 84.7%，所以我们构建了一套更难的离线数据集，共 3,148 道题：其中 2,850 道参照 FinSearchComp 在固定数据快照上生成，答案由程序计算并由另一套独立实现复核，另有 98 道 FinSearchComp 和 200 道 DocFinQA 测试题。Qwen3.8-27B 教师在 agent harness 中做两档难度的行情训练题，过滤后的这些轨迹，连同过滤后的财富管理和机器学习轨迹以及取自 1:1 混合数据的 2,000 条对话，用多轮 agent SFT 训练 4B 模型。在 300 道行情测试题上（股票是留出的，指数、ETF、外汇和 FRED 序列用更晚的时间段），SFT 模型做对 88.7%，官方 Qwen3.5-4B 为 57.7%，起点模型为 16.7%，教师为 94.7%。从 SFT 模型出发的 GRPO 强化学习正在进行。

这一环把公开的金融和通用数据加工成监督微调（SFT）用的训练数据。这些混合数据用于单轮 SFT 的运行；第 4 环的 agent SFT 模型只从 1:1 混合数据中取 2,000 条对话。

  • 统一格式：每个来源都改写成同一种样本格式，包含编号、来源、对话和元数据。后面的步骤才能用同一套代码处理所有来源。改写时丢弃超过 4,096 token 的样本而不截断，因为截断会留下推理、丢掉答案。
  • 合成文档问答：模型 gpt-oss-120b 读一段 1,000 到 2,000 字符的财经文档，出一道计算题并写出解答。这把“读材料、算数字”的题型扩展到年报之外。只有用到的数字都出现在文档中，且根据同一文档再答一次的结果相差在 1% 以内，样本才保留。
  • 去污染：这一步删除与评测题重复或高度相似的训练样本。否则分数可能来自模型已经见过的题。样本在四种情况下被标出：连续 8 个 token 的重合片段覆盖某道评测题至少一半；去掉表格和 JSON 格式后再比一次仍如此；两个嵌入模型之一判定过于相似；与年报摘录共有足够多的数字。
  • Grounding 过滤：这道过滤删除金融指令数据集 IndustryInstruction 中答案用了提示之外材料的样本。这类样本会教模型写出材料里没有的数字。提示很短却提到它没有给出的文章或数据，或者答案里有两个以上提示中没有的具体数字，样本就会被删。
  • 去重：这一步让每道题只留一条样本。同一道 FinQA 题也出现在 DianJin 和 BizBench 数据集中，FinQA 的版本排在最前，因为它的解答由标准程序得出。带文档摘录的样本在问题规范化后相同、且摘录数字集合的 Jaccard 相似度不低于 0.5 时算同一题；其余样本按精确匹配或 MinHash 相似度 0.9 判断。
  • 混合：每次 SFT 运行按设定比例，从 143,442 条的金融池和 829,947 条的通用池中抽取 100,000 条样本。只用金融数据做 SFT 可能抹掉底座模型的通用能力，所以比例决定了用多少通用数据来保住这些能力。金融来源按规模抽样，单个来源最多占 40%，小样本嵌套在大样本里。

Harness 把模型包起来做多步任务：提供系统提示和工具，执行工具调用，检查答案并判分。模型调用 finish 工具提交答案来结束任务。下面描述第 3 版的完整配置，教师做行情题时用的就是它。

  • 只追加的上下文：消息发出后不再改动，所以每次调用模型的消息都是下一次调用和所存轨迹的前缀。这样行情 SFT 数据和 GRPO 用的就是模型当时看到的消息序列。较早的结果从不压缩成摘要；每个工具结果在产生时截到 8,000 字符，并附一句说明如何少取一些。
  • 清单工具：set_checklist 让模型写下完成请求所需的步骤，并标记已完成的步骤。它让长任务中的子目标始终可见。Harness 在每次工具返回后复述清单，一个任务最多调用 20 次。
  • 步数分开计：100 步的上限只计任务轮，也就是做任务本身的轮次。维护清单和重做被驳回的答案，不应占用长任务需要的步数。只调用清单工具的轮、被驳回的 finish 那一轮及其后 10 轮都不计入，总轮数硬上限为 142。
  • 约束：每次写操作执行前，代码都按工具 Schema 和可检查的业务规则检查一遍。违反规则的交易不应落到账户上。违规的写操作会被拒绝且不执行，模型收到原因。行情工具只读数据，所以这一部分只在财富管理环境中起作用。
  • 答案校验：模型调用 finish 时，答案里的数字（日期等例外）要在工具结果或请求中有依据，清单要全部完成，环境自己的检查也要通过，比如每笔交易在最终状态下都符合规则。这针对没有工具算出过的数字和工作没做完就交的答案。在行情题上，工具结果中的数字经过千、百万、十亿或百分比换算，再按答案的小数位取整后相等，就算有依据。校验不通过时最多驳回两次；再下一次 finish 不经校验就接受，SFT 的过滤会去掉这样的轨迹。
  • 纠错消息：这些消息告诉模型哪里出了问题。它们的目的是减少陷入循环和浪费步数。被驳回的 finish 返回未通过的检查项，已知工具报错时返回一个正确调用的示例，第三次相同调用时提示换思路，没有调用工具的回复会收到提醒。
  • 保留思考的对话模板：这个改过的 Qwen3.5 模板用于在 harness 第 3 版中服务 4B 模型，以及渲染行情 SFT 数据，保留第一条用户消息之后每个助手轮的思考。原模板在提醒之后丢掉较早的思考，下一轮的提示就不再是上一轮的延续。每轮都记录采样的 token，以及本轮提示是否以上一轮的提示和生成内容开头，所以任何断开都能查出来。

Qwen3.8-27B 教师的行情轨迹最多通过 11 道过滤，比如答对、不重复调用、教师核对方法，以及限制底座模型已经会做的题。财富管理和机器学习轨迹通过其中适用的 7 道。它们连同取自 1:1 混合数据的 2,000 条对话共 12,475 条样本。多条样本拼进一条长度不超过 32,768 token 的训练序列，共 2,439 条序列。训练微调 Qwen3.5-4B-Base 的全部参数，共 2 个 epoch，学习率 1e-5，用 6 张 GPU。

  • 损失：训练最小化模型下一个 token 的预测与标签之间的交叉熵，也就是标准的 causal LM 损失 \(\mathcal{L} = -\frac{1}{N}\sum_{t:\, y_t \neq -100} \log p_\theta(y_t \mid x_{<t})\)，其中 \(x_{<t}\) 是位置 \(t\) 之前的序列，\(\theta\) 是模型权重，\(N\) 是带标签的 token 数。这让模型逐 token 复现带标签的轮。损失只在带标签的位置计算，并分块在反向传播时重新计算，数值和梯度都不变，又省下了每个位置全词表 logits 占用的显存。
  • 标签：需要模型学习的位置，标签就是该 token 本身；其余位置为 −100，损失会忽略。工具输出来自工具，所以不模仿。标签覆盖轨迹的助手轮：思考、文本和工具调用，直到结束符。系统、用户和工具轮都被屏蔽。行情轨迹另外不计招来提醒的回复和含被驳回调用的轮，它们留在上下文里。财富管理和机器学习轨迹的被驳回轮仍计损失，带提醒的轨迹整条去掉。当前的数据构建代码还会屏蔽调用格式错误的轮，比如不存在的工具名；SFT 模型的数据建于这条规则之前，这些轮占它带标签 token 的 0.25%。
  • 样本边界：每个批次都告诉模型，同一条序列里每个样本从哪里开始、到哪里结束。否则 Qwen3.5 的线性注意力层会把状态从一个样本带到下一个。加上边界后，这一泄漏造成的每 token 损失最大差异从 6.3 nats 降到 0.13 nats，属于数值噪声。

程序在下面的数据集上给每个 SFT 模型打分。两个模型按题配对比较：\(\Delta = \frac{1}{n}\sum_{i=1}^{n}(b_i - a_i)\)，其中 \(a_i\)、\(b_i\) 做对为 100、做错为 0，95% 区间由对 \(n\) 道题的 10,000 次配对 bootstrap 重抽得到。

单轮 SFT 的运行

  • 金融分（1,886 道 FinQA 和 TAT-QA 测试题）：最后一个 "Answer:" 之后的第一个数与标准答案相差 1% 以内算对，百分数和小数两种写法都认。其中 \(D\) 是题目集合，\(y_i\) 是标准答案，\(\hat{y}_i\) 是回答，\(\tau_i = 0.01|y_i|\)，\(y_i = 0\) 时为 0.005。\[A_{\text{fin}} = \frac{100}{|D|}\sum_{i \in D}\mathbf{1}\Big[\min_{k \in \{1,\,100,\,0.01\}}|k\hat{y}_i - y_i| \le \tau_i\Big]\]
  • MMLU（13,018 题）：这个知识评测去掉了四个经济和会计科目，对提示 \(x_q\)，概率最大的选项 \(o\) 是正确选项 \(o^{*}_q\) 就算对；\(Q\) 是题目集合。\[A_{\text{MMLU}} = \frac{100}{|Q|}\sum_{q \in Q}\mathbf{1}\Big[\arg\max_{o}\log p(o \mid x_q) = o^{*}_q\Big]\]
  • GSM8K（1,319 题）：数学应用题的回答中，最后一个数 \(\hat{a}_q\) 等于标准答案 \(a_q\) 算对；\(Q\) 是题目集合。\[A_{\text{GSM}} = \frac{100}{|Q|}\sum_{q \in Q}\mathbf{1}[\hat{a}_q = a_q]\]
  • IFEval（541 条提示）：回答满足这条提示中所有可由程序检查的指令 \(I_p\)（如字数上限或 JSON 输出）才算对；\(P\) 是提示集合，指令 \(j\) 成立时 \(f_{p,j}=1\)。\[A_{\text{IF}} = \frac{100}{|P|}\sum_{p \in P}\prod_{j \in I_p} f_{p,j}\]
  • 通用分：三项通用评测的平均。\[A_{\text{gen}} = \tfrac{1}{3}(A_{\text{MMLU}} + A_{\text{GSM}} + A_{\text{IF}})\]

Agent SFT 模型

  • 行情测试集（300 题）：标准答案的每个键（容差内的数值、日期、文本或集合）都在最终答案中正确出现，题目集合 \(T\) 中的这道题才算通过（\(s_t = 1\)）。\[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • FinSearchComp 离线（98 题）：按同样的键规则判，容差取每题写明的值。\[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • DocFinQA（200 题）：针对整份 SEC 10-K 的问题，agent 给出的数与标准答案相差 1% 以内算通过，规则同金融分。\[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • 财富管理 + 机器学习（550 题）：500 个财富管理任务要求最终持仓、现金和交易记录与标准状态一致，且答案中的关键数值在误差内；规则禁止的任务要求不执行被禁止的交易，并在答案中指出规则。50 道机器学习任务要求提交模型，且指标比生成数据的模型低不超过 0.015 AUC 或 0.03 \(R^2\)。\[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • 开发集（200 题，每题 4 次）：pass@1 是单次尝试的平均通过率，pass@4 是至少做对一次的题的比例；\(T\) 是有 4 次有效尝试的题，题 \(t\) 的 \(n_t\) 次有效尝试中有 \(c_t\) 次通过。\[P_1 = \frac{100}{|T|}\sum_{t \in T}\frac{c_t}{n_t}, \qquad P_4 = \frac{100}{|T|}\sum_{t \in T}\mathbf{1}[c_t \ge 1]\]

在 verl 上从 SFT 模型继续做 GRPO，并消融三个因素：按 SFT 模型通过率筛选的训练题、每步更新次数和 DAPO 式动态采样。GRPO 1 已完成，GRPO 2 正在训练。

  • GRPO：这种强化学习方法对每道题采样一组尝试，按组内相对表现给每次尝试打分。组内均值就是基线，所以不需要价值网络。每步在强化学习框架 verl 上取 96 道题，每题 8 次尝试，判分通过的尝试奖励为 1，否则为 0。
  • 消融：每个 setting 只比前一个改一项。相邻 setting 的分数差就能归到这一项上，只是 GRPO 1 和 2 还差在 GRPO 1 的前 4 步。下表列出 4 个 setting。
  • 通过率筛选：SFT 模型对每道候选训练题做 8 次，由通过率决定去留。同一题的尝试奖励都相同时，GRPO 没有可比较的东西。在 2,000 道新生成的题中（与 SFT 题和生成的开发题、测试题都不重复），一次都没做对的去掉，有时做对的保留，每次都做对的留 10%；再按题型把留下的 1,123 道抽到 939 道，与 GRPO 1 的题数相同。
  • 每步更新次数：指模型权重在一批尝试上更新几次。它决定模型在每批昂贵的数据上走多远。mini-batch 从 96 道题改成 24 道，每步更新 4 次，总共 112 次。
  • DAPO 式动态采样：一组 8 次奖励全相同的尝试会被丢掉，并在这一步内补上新题。这样的组优势为零，耗费生成时间却没有信号。每丢一组补 2 道题；一步派发到 288 道题（批大小的 3 倍）后，这一步不再过滤。
  • 尝试上限：一次尝试最多 30 个任务轮，提示之后 28,672 token 的预算（含工具结果）。加上 4,096 token 的提示，正好对应 32,768 token 的 SFT 序列。超出预算被截断的尝试在组内仍记奖励 0，但不计损失，因为截断不是模型的选择。

SFT 模型和每个 GRPO setting 的最后一个检查点都跑下面的数据集，所以结果能按题配对。

  • 行情测试集（300 题）：题目集合 \(T\) 中的每道题按与 SFT 评测相同的键规则判定通过（\(s_t = 1\)）。\[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • 严格行情判分（同样 300 题；FinSearchComp 和开发集也跑）：答案还要满足四条规则（\(r_t = 1\)）：日期之外最多 50 个数字；最多 40 个不同日期；每个数值键都在日期之外找到；有候选的题首先点名的公司要正确，其后每个公司键都紧跟它的数值。\[S_{\text{strict}} = \frac{100}{|T|}\sum_{t \in T} s_t\, r_t\]
  • FinSearchComp 离线（98 题）：每道题按与 SFT 评测相同的键规则判定通过。\[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • DocFinQA（200 题）：与标准答案相差 1% 以内算通过，同 SFT 评测。\[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • 财富管理 + 机器学习（550 题）：每道题按与 SFT 评测相同的状态和指标规则判定通过。\[S = \frac{100}{|T|}\sum_{t \in T} s_t\]
  • 开发集（200 题，每题 4 次）：pass@1 和 pass@4 的定义同 SFT 评测，\(T\) 是有 4 次有效尝试的题，训练期间每 4 步也在这些题上验证一次。\[P_1 = \frac{100}{|T|}\sum_{t \in T}\frac{c_t}{n_t}, \qquad P_4 = \frac{100}{|T|}\sum_{t \in T}\mathbf{1}[c_t \ge 1]\]
  • 换措辞的行情测试集（300 题）：同样的题换一种措辞，参数和答案不变，分数变化说明成绩有多依赖措辞。\[\Delta_{\text{reword}} = S_{\text{reworded}} - S_{\text{original}}\]
  • 通用能力（MMLU、GSM8K、IFEval）：三项按 SFT 评测的方式打分，只是 IFEval 用模型自己的对话模板，而不是单轮运行的训练模板，并且只给思考之后的文字打分。\[A_{\text{gen}} = \tfrac{1}{3}(A_{\text{MMLU}} + A_{\text{GSM}} + A_{\text{IF}})\]
  • 相对 SFT 模型的提升：在上面每个按题评测的数据集上，\(a_i\) 是 SFT 模型、\(b_i\) 是检查点在题 \(i\) 上的得分，配对 bootstrap 同 SFT 评测。\[\Delta = \frac{1}{n}\sum_{i=1}^{n}(b_i - a_i)\]
