摘要

本项目拟用五个数据集，对 Qwen3.5-4B-Base 比较九组后训练设置：原有金融问答与指令遵循任务，加上 FinDeepResearch 公司研究报告和源自 Kaggle 的 MLE-bench 项目子集。多轮监督微调（SFT）让模型学习经过核验的示范，DAPO 再通过工具试答与任务各自的奖励学习。合成增量计划用于 FinSearchComp 及两个新增数据集；DocFinQA 与 IFEval 仅用原题。所有设置将共用冻结的原始队列和评测协议，以分别检验在 SFT、DAPO 或两个阶段加入合成任务的作用。新增任务适配器仍待证据、评分与执行资格核验，新一轮训练尚未开始。

方法管线

点击下面的环节查看它做什么。

→ → → → → →
规范报告 → 任务约束 → 来源隔离 → 冻结题目池

每份财报只引用一个原始版本

  • Canonicalization: 入口按注册主体与财年结束日期归并 DocFinQA 报告，依据来源质量选择一份原文，并保留其他版本及来源哈希，避免等价报告被当成不同材料。
  • Evidence retention: 选择后的检查隔离丢失必要运算依据的问题；检查不改写报告，也不依据模型成绩选择报告版本。

共同外层接口保留各任务的原生输出

  • Task adapter: 计划中的五数据集接口将来源身份与输入文件、隔离的工具轨迹、提交产物及各数据集评分结果绑定起来；共用这份外层记录，让同一运行器管理不同任务，同时保留报告写作和机器学习工程的任务形式。
  • Qualification: 新适配器须先通过证据访问、原生评分、产物格式与评分端隔离检查，再准入任务；数据集表定义任务输出和指标，题目池表区分已冻结队列与可执行任务。

先核对来源身份，再抽取题目

  • Decontamination: 划分器跨集合核对报告身份、规范化题面、题目派生关系及金融答案支持期间；身份未识别的报告留在合格题目池之外。
  • Stratification: DocFinQA 保留官方划分归属，按数值／布尔类别比例各保留一半；FinSearchComp 与 IFEval 使用确定性的类别分层项目划分，以保留类别覆盖及足够的测试题。

一个版本服务所有模型设置

  • Immutable inputs: 现有原题 ID、原始文本、规范报告与评分器绑定到冻结版本；新增队列及适配器通过资格核验后才并入共同版本，数量与状态见候选设置表。
  • Reserved evaluation: 合成验证、测试题使用隔离的答案支持来源并独立审查；不能用重复题或未审查候选填补验收配额。
程序支线 Claude 支线 原生请求

程序扩展可复现的薄弱题型

  • Programmatic generation: 生成器在可信金融事实和明确期间、单位、计算约束内改变题目参数，为解题不稳定或持续出错的能力提供可重复练习，不复制保留题。

Claude 在已验证约束内选择题目

  • Source-bound generation: Claude 从可信来源实例与训练能力中选择支持的题目结构及参数；编译器控制学习者题面与参考计算，防止生成文本暗中引入事实或权威答案。
  • Scope: 当前有类型约束的适配器覆盖有限的 SEC 检索与债务计算题；不支持的结构被拒绝，适配器不宣称覆盖整个 FinSearchComp。

各角色使用独立的原生 Messages 请求

  • Native proxy: 客户端通过 CLIProxyAPI 的原生 Messages 接口使用明确的自定义提示，每个角色使用独立对话；Opus 5.5 出题采用 Extra High，盲解、对抗审查及轨迹审查采用 Medium。
  • Accounting: 共享的追加式账本约束总额度、调用次数与各角色单次上限；失败请求仍被记录，缺失计量时阻止后续调用。
独立答案 → 工具执行 → 盲解与对抗审查

独立计算核对答案约束

  • Reference agreement: 独立算术实现必须在答案、单位与所需来源期间上相符；等价数学实例先去重，再计入配额。

真实工具核对数据可得性

  • Sandbox replay: 现有金融问答的参考代码通过学习者的受限工具环境查询固定只读快照，执行结果须与独立答案一致；计划中的报告、机器学习任务须分别通过原生产物及评分检查，元数据声明不能单独证明任务可执行。

盲解与对抗审查保持独立

  • Blind solve: 独立 Claude 对话只接收学习者题面与工具约束，不接收私有答案；其求解程序随后被实际执行并独立评分。
  • Adversarial review: 另一独立对话检查题目、参考答案、程序及执行结果中的歧义、期间、单位和评分漏洞，不接收前次审查结论；两种审查均通过后才准入题目。
智能体框架 → 难度测量 → 示范准入

框架记录模型实际使用的证据

  • Tool interface: 现有金融问答使用只读市场、SEC、FRED 查询、报告检索与受限 Python 环境，消息、工具调用及返回被保存为轨迹，明确提交后结束试答；计划中的报告与机器学习适配器将挂载来源证据或竞赛文件，并将专家目标和隐藏标签排除在学习者工具之外。
  • IFEval: 严格指令检查器仅评分最终答案并固定评分随机性；金融数值证据要求不应用于纯指令任务。

本地模型在训练前测量可解性

  • Teacher and student: 较大的本地教师提供候选示范，学生多次试答测量成功模式；始终不会的题先诊断或补充 SFT 示范，不自动视为有效 DAPO 训练信号。
  • Reserved tasks: 校准只使用训练或校准材料，封存测试不参与难度筛选。

仅有正确最终答案不足以准入

  • Trace qualification: 准入核对成功的证据读取、工具格式、事实依据、单位、完成状态与来源凭据；历史轨迹不能在缺少匹配来源证据时自动换绑到新报告。
  • Separate products: 合格题、合格示范与打包训练数据是不同输出；缺少示范或仍未审查的候选会使训练入口保持关闭。

六个强化学习作业补全九组设置

  • Matched continuations: 两个 SFT 检查点和原始 Base 模型分别接受原题或加合成的 DAPO 继续训练，共用题目池的关系在基线表中标明。
  • Dynamic filtering: DAPO 过滤奖励没有差别的回答组；记录过滤后真正进入更新的任务、更新次数、生成 token 和工具计算曝光量，计划中的报告及机器学习评分到奖励的适配须先通过资格核验。

软长度惩罚只统计模型生成内容

  • Generated-token penalty: 项目奖励管理器从软长度惩罚中排除工具返回、插入上下文与填充；硬响应预算仍包含全部上下文，保留明确的资源上限。

未完成试答不参与策略损失

  • Whole-rollout masking: 未完成的截断或中止回合整条策略掩码归零；完成但答错的回合仍可训练，全掩码小批次保持有限损失与梯度。
  • Launch gates: 两项修复已实现并通过 CPU 检查，新一轮六个强化学习作业尚未开始；共同数据、检查点与可执行预算控制就绪后才能启动。

各阶段使用同一批原始任务测量

  • Native metrics: 每个数据集采用数据集表中的指标定义与公式，分别报告问答准确率、严格指令遵循、报告质量和机器学习竞赛表现，并注明各指标方向及评测队列。
  • Shared protocol: Base、SFT、DAPO 结果使用相同题目 ID、工具条件、采样规则与评分器版本，以支持阶段之间的比较。

新增测试检验独立审查后的合成任务

  • Separate reporting: 各个合格合成挑战与原题队列分开报告；项目派生的报告或机器学习挑战保留各自任务要求和评分器，其成绩不替代官方原始基准成绩。
  • Limits: 扩大的合成测试测量生成题族的覆盖；泛化结论限于实际评测过的保留来源、题族与执行预算。

配对差异检验声明的数据变化

  • Stage comparisons: 比较 S1 与 S0 检验 SFT 增量；从同一检查点比较加合成与原题 DAPO 检验 DAPO 增量；将 DAPO 结果与自身起点比较检验额外训练的作用。
  • Selection: 只有验证集用于选择检查点和混合配比；最终配对置信区间使用相同冻结测试，不反馈给出题器。
